**Design decisions**
- New `agent_callstack/invocation.py` — `InvocationFactory`, a frozen,
  purely-config value object that owns the nested-vs-root identity decision
  and child-env propagation. Captures only a Caller's static config
  (explicit_cwd / log_dir / invoke_id / max_depth) and reads process env
  LAZILY at call time — so a host that pops stale CALLSTACK_ROOT_* between
  Caller construction and use (mcp_server does exactly this) still gets the
  corrected decision. Reads env via Task-2's public env helpers
  (root_identity / frame_key / claude_code_session / in_nested_invocation)
  rather than poking os.environ keys.
- Interface: parent_project_cwd(), effective_cwd(), effective_log_dir(),
  context(parent_cwd) [the nested-vs-root branch], child_env(ctx, depth_base).
- Caller keeps the behavioural seams `_parent_project_cwd`,
  `_resolve_invocation_context`, `_driver_for` but they become thin
  delegations to `self._inv`. `_effective_cwd` / `_effective_log_dir` removed
  (callers go through the factory). Channel/trace/store wiring stays in Caller
  — that's runtime config, not identity. Caller class shrank ~248 → 180 LOC;
  the ~95 LOC of identity helpers became ~25 LOC of delegation.
- mcp_server.py: NO change needed. It keeps its own `_invocation_identity`
  (validate inherited dir exists, pop stale env, mint for the envelope) — a
  boundary-adapter concern distinct from building a context. It already uses
  the public `root_identity()`; the factory uses the same primitive, so it's
  one rule with two consumers, not duplicated logic. Confirmed it still
  imports only top-level public `agent_callstack` names (Task 2 preserved).
